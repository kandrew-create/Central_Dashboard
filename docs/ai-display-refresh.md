# Saved Local AI state and results

Central Server 0.6.2 loads its saved Local AI configuration and stored interpretations when the manager opens and whenever **5 Equipment Identification** (**5 Local AI** in earlier builds) is selected. It also includes these results in the normal server refresh. Selecting the tab during another operation defers the read until that operation finishes. All reads run off the GUI thread.

The current manager names this tab **Equipment Identification** and explains that the AI model is installed on the Central Server PC. Identification includes uploaded records from registered sources on other collector PCs, with source names shown per row; the view is limited to 200 results from this server's database and does not combine separate Central Servers. Events use registered machine tags without AI. Tab spacing accommodates the longer title at minimum window size. This wording change does not install a model or change processing, database queries or saved state. The updated local 0.6.2 package is installed on this development PC; published X3 retains its earlier label.

**Enable local AI** and **Disable** change processing settings. Opening the window, selecting the tab and **Refresh interpretations** only read saved settings/results; they do not enable AI, call the model or create SCADA revisions. Results saved while AI was enabled remain viewable when it is disabled. With PostgreSQL stopped, the saved setting/model are still shown and the tab explains that Central Server must start to load its stored results. A model typed but not yet enabled is preserved across automatic reads.

An AI settings/read failure is displayed in the AI tab without replacing a successful server-settings save confirmation or the normal server-health result. Original alarm/event records, equipment identifications, source names, queue behavior and approved mappings are unchanged. There is no database migration.
